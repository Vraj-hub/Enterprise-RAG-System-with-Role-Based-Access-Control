# Enterprise RAG System with Role-Based Access Control

A local FastAPI application that lets people ask questions about company documents, while making sure each user can only retrieve what their **role, department and clearance** allow. Documents are indexed into ChromaDB (vector search) and SQLite FTS5 (keyword search), and answers are generated by a local LLM through [Ollama](https://ollama.com). Nothing leaves your machine.

## Features

- **Role-based access control (RBAC)** applied *before* retrieval: the language model never sees chunks the user is not allowed to read.
- **Hybrid retrieval**: vector search plus BM25 keyword search (SQLite FTS5), merged with Reciprocal Rank Fusion. Both retrievers only see authorized documents.
- **Relevance gate**: weak matches are dropped, so unrelated questions get "not enough information" instead of a guess.
- **Verified citations**: answers cite sources as `[1]`, `[2]`. Invented citation numbers are stripped, and only passages the answer actually used are shown, with page numbers and a click-to-open preview.
- **Conversations**: private chat history and follow-up questions. When an old chat is reopened, sources the user can no longer access are redacted. Earlier answers are never replayed to the model, only earlier questions.
- **Admin tools**: analytics dashboard (unanswered questions, latency p50/p95, blocked matches, injection flags), system health with Ollama model checks, user management and a filterable audit log.
- **Authentication**: username/password login with JWT, self-service sign-up (open / approval / off) and optional Google sign-in.
- **Document ingestion**: PDF, DOCX, TXT and Markdown uploads (up to 10 MB each).
- **Hardening**: strict Content-Security-Policy, security headers, no default JWT secret, login throttling and prompt-injection pattern flagging in the audit log.
- **UI**: dark mode, answer status line, evidence cards colour-coded by sensitivity, thumbs up/down feedback.
- **Evaluation script**: measures retrieval hit rate and unauthorized leaks (must be 0).

## How it works

```
Upload ──► extract text ──► split into chunks ──► embed (Ollama) ──► ChromaDB
                                      └────────► keyword index ───► SQLite FTS5

Question ─► RBAC filter (role, department, sensitivity)
         ─► vector search + keyword search (authorized docs only)
         ─► Reciprocal Rank Fusion ─► relevance gate
         ─► LLM answers from the allowed passages only (Ollama)
         ─► citations verified ─► answer + sources + audit log entry
```

The RBAC filter is applied inside the Chroma query, and the keyword search is limited to the authorized document list. The LLM receives only the authorized hits.

## Access rules

A chunk is readable only if **all** of these are true:

1. The user's role is in the document's `allowed_roles`.
2. The document's sensitivity is within that role's clearance.
3. The document belongs to the user's department or is company-wide (`all`). Admins can access across departments.

Self-registered accounts are always `employee` in the configured sign-up department (default `general`), so they only see company-wide documents.

## Prerequisites

- **Python 3.10, 3.11 or 3.12** (64-bit). Newer versions such as 3.15 may lack prebuilt wheels for `chromadb` and `numpy` and fail to install.
- **[Ollama](https://ollama.com)** installed and running.
- These models pulled:
  - `nomic-embed-text:latest` for embeddings
  - `qwen3:8b` for answers (`qwen2.5:7b` also works; set `OLLAMA_MODEL`)

```bash
ollama pull nomic-embed-text
ollama pull qwen3:8b
ollama list
```

## Quick start

### Windows (PowerShell)

Run from the folder that contains `seed.py`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
python seed.py
python run.py
```

If PowerShell blocks activation, use Command Prompt and run `.venv\Scripts\activate.bat`. Do not disable Windows application-control policies.

### macOS / Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
nano .env
python seed.py
python run.py
```

Then open **http://127.0.0.1:8080**. Interactive API docs are at **http://127.0.0.1:8080/docs**.

Without `run.py`, the equivalent is:

```bash
python -m uvicorn app.main:app --reload --port 8080
```

> In `.env`, set `JWT_SECRET` to a long random value. Generate one with:
> `python -c "import secrets; print(secrets.token_urlsafe(48))"`
> If it is empty or shorter than 32 characters, the app uses a temporary secret and everyone is logged out on each restart.

Check that Ollama works before uploading documents:

```bash
ollama run nomic-embed-text "Enterprise document security"
ollama run qwen3:8b "Explain role-based access control in three sentences."
```

## Configuration

All settings live in `.env` (copy from `.env.example`).

| Variable | Default | Purpose |
|---|---|---|
| `JWT_SECRET` | *(none)* | Signing key for login tokens. 32+ characters. |
| `JWT_EXPIRE_MINUTES` | `60` | Token lifetime. |
| `APP_HOST` / `APP_PORT` | `127.0.0.1` / `8080` | Where `run.py` listens. |
| `EMBEDDER` | `ollama` | `ollama`, `st` (sentence-transformers) or `hash` (tests only). |
| `OLLAMA_URL` | `http://localhost:11434` | Ollama server address. |
| `OLLAMA_EMBED_MODEL` | `nomic-embed-text:latest` | Embedding model. |
| `OLLAMA_MODEL` | `qwen3:8b` | Answer model. |
| `OLLAMA_EMBED_CPU_ONLY` | `0` | Set to `1` if the Ollama runner crashes on the GPU. |
| `DATA_DIR` | `./data_nomic` | Folder for the SQLite DB, Chroma index and uploads. |
| `MIN_RELEVANCE` | `0.35` | Minimum cosine similarity for a vector-only hit. |
| `CANDIDATES` | `12` | Candidates per retriever before fusion. |
| `SIGNUP_MODE` | `approval` | `open`, `approval` or `off`. |
| `SIGNUP_DEPARTMENT` | `general` | Department for self-registered users. |
| `SIGNUP_EMAIL_DOMAINS` | *(empty)* | Optional allow-list, e.g. `company.com`. |
| `SIGNUP_RATE_PER_HOUR` | `5` | Sign-up rate limit. |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | *(empty)* | Enable Google sign-in. |
| `GOOGLE_REDIRECT_URI` | `http://127.0.0.1:<APP_PORT>/api/auth/google/callback` | Must match your Google console setting. |

**Important:** never point `DATA_DIR` at a Chroma index created with a different embedding model. If you change embedding models, use a fresh data directory and re-index your documents.

## Using the app

1. **Log in** with a demo account (or sign up if `SIGNUP_MODE` allows it).
2. **Ask a question** in the chat. The answer shows citations, and each source card can be opened to see the exact passage.
3. **Upload documents** (PDF, DOCX, TXT, MD). Set the department, sensitivity and allowed roles when uploading.
4. **Try the RBAC behaviour**: ask "What are the salary bands?" as `eng_emp` (no access) and then as `hr_mgr` (allowed). The restricted acquisition plan is visible to `admin` only.
5. **Admins** can use the analytics dashboard, system health page, user management and audit log.

## Tests and evaluation

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

The test suite uses the lightweight `hash` embedder and a deliberately unreachable Ollama endpoint, so it does not need a local model.

On Windows, if pytest fails with a DLL error from the `langsmith` plugin, disable plugin auto-loading first:

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = "1"
python -m pytest -q
```

Retrieval evaluation (requires Ollama and a seeded database):

```bash
python -m eval.run_eval
```

It reports the retrieval hit rate and the number of unauthorized leaks, which **must be 0**. Add your own questions in `eval/questions.json`.

## Troubleshooting

| Problem | Fix |
|---|---|
| `pip.exe` / `uvicorn.exe` blocked by an Application Control policy | Use `python -m pip ...`, `python -m uvicorn ...` or `python run.py`. |
| `WinError 10013` when starting the server | The port is reserved or in use. Change `APP_PORT` in `.env` (e.g. 8080, 8765) and keep `GOOGLE_REDIRECT_URI` in sync. |
| pip tries to compile `numpy` and fails with "Unknown compiler" | Wrong Python version. Recreate the venv with Python 3.11 or 3.12. |
| `DLL load failed while importing _xxhash` during pytest | Set `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` (see above). |
| Connection refused on port 11434 | Ollama is not running. Start the Ollama app or run `ollama serve`. |
| Ollama returns `500` while indexing | Check the `error` field. A `llama-server` crash (e.g. exit status `0xc0000005`) means the model runner crashed. Update or restart Ollama, run `ollama pull nomic-embed-text`, and try `OLLAMA_EMBED_CPU_ONLY=1`. |
| Answers say the model is unavailable | The `OLLAMA_MODEL` in `.env` is not pulled. Check `ollama list`. |
| Chroma or embedding errors after changing models | The index was built with a different embedding model. Delete `data_nomic/` and run `python seed.py` again. |
| Documents from an older version have no keyword index or page numbers | Delete `data_nomic/` and run `python seed.py`, or re-upload them. |

## Known limitations

- Scanned PDFs may not yield text. OCR is not implemented.
- `MIN_RELEVANCE` (default 0.35) is a starting point, not a calibrated value. Tune it with `eval/run_eval.py` on real documents.
- The login throttle is in-memory and meant for a single-process demo.
- SQLite is for local development. Production use needs stronger operational controls, secret management, HTTPS, monitoring and a reviewed authorization design.
- Prompt-injection resistance is defense-in-depth, not a guarantee. Model-generated answers are not a substitute for security review.

## Security notes

- Keep `.env` out of version control (it is in `.gitignore`). Never share it or a zip that contains it.
- Do not commit runtime data: `data_nomic/` holds the database, vector index and uploaded files.
- Change all demo passwords and set a strong `JWT_SECRET` before any use beyond local testing.
- Serve over HTTPS and put the app behind a reverse proxy if you ever expose it beyond localhost.
